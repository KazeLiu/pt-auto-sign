# TTG 签到前后对比与修复记录

验证日期：2026-10-10。页面：`https://totheglory.im/my.php`。

## 实站取证

整个实站验证只点击一次签到按钮，只产生一次 `POST /signed.php`，没有重放请求。页面切换导致的保护检查失败均发生在点击前，没有产生签到请求。使用同一 Chrome 登录会话的独立标签页完成取证。

| 时刻 | 页面与插件结果 |
| --- | --- |
| 点击前 | `.smallfont #sp_signed` 文本为“签到”，包含 `a#signed`，链接为 `javascript:void(0);`；旧选择器能正确命中 |
| 点击后约 3 ms | 旧策略已返回 `sign: false`、`pending: true`、`status: action-triggered`，提示“已触发签到，待确认”；页面仍显示签到按钮 |
| 请求完成约 1186 ms | 唯一一次 `POST /signed.php` 返回 HTTP 200 |
| 点击后约 1210 ms | `#sp_signed` 改为“已签到”，签到链接消失；站点弹窗提示连续签到 2 天，本次奖励 11 积分 |
| 接受提示并只刷新页面 | 仍显示“已签到”，没有签到按钮；确认状态已保存到站点 |

站点的 jQuery 点击处理器携带当前页面生成的 `signed_timestamp`、`signed_token` 发起异步 POST，回调更新 `#sp_signed` 并显示弹窗。记录不包含 Token 值、Cookie 或个人页面内容。

## 根因与修改

入口选择器没有失效。旧策略点击后立即返回待确认，调度器对 `action-triggered` 不重试，并会在非调试模式关闭标签页；既不能记录稍后到达的成功状态，也可能在请求完成前关闭页面。

`ttgMain` 改为异步等待：先观察签到区域，再点击原站点按钮一次，等待明确的“已签到”状态，最长 15 秒。观察到结果后才返回 `signed`，使调度器等待回执后再关闭标签页。超时仍返回待确认，不把按钮消失或 HTTP 200 当成成功。文档级标记防止同一页面重复注入或并发执行造成再次点击。

## 验证范围

- 先用旧实现跑回归用例，6 项中 5 项失败，捕获立即返回、空白文本识别、无等待超时及重复注入点击的问题。
- 修复后 6 项 TTG 回归用例通过；覆盖异步成功、已签到、超时与迟到结果、按钮消失但未确认、无入口，以及同一文档并发注入不重复点击。
- `npm test` 全量 13 项测试通过；`npm run build` 成功，产物位于 `dist/`。构建保留既有 Sass legacy API 和包体大小提示。
- 原标签页刷新后也显示“已签到”。将修改后的函数本体注入真实页面，返回 `sign: true`、`pending: false`、`status: signed`；只读验证的点击次数为 0，没有新增签到 POST。
- 真实未签到状态仅用于这次旧逻辑取证，不会再次执行真实签到；修复后已签到分支在真实页面做只读验证。新版点击到成功的完整链路通过与实站变化一致的模拟 DOM 验证，尚未在下一次未签到状态实测。
